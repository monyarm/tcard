# tcard — design

Terminal tool that turns a tabletop record into a printable card on stdout, so it
can be piped into `tp` (thermal printer, 58 mm paper, 384 dots wide).

```
tcard dnd:5e spell fireball | tp
tcard fireball | tp
```

## Decisions

| Decision | Value | Why |
|---|---|---|
| Language | Python 3.11+ (stdlib only) | `tp` is Python; zero build step, no deps to vendor |
| First system | dnd:5e (5e.tools data) | Data is complete, JSON, one file per book |
| First kind | spell | Proof of concept |
| Binary | `tcard` | Free on PATH, short to type before a pipe |
| Default output | full spell text | A card is the rules text, not a summary |
| Width | 32 cols default, `--cols N` | tp's default font gives 32 columns; see below |
| Renderer | `Card` -> `[Line]` -> backend | PNG backend draws the same lines later |
| PNG backend | delegated to a later change | Needs the tp stdin change; not part of v1 |

## tp constraints (read from `~/.nix/packages/tp.py`)

- 384 dots wide. Text columns = `384 // round(char_advance)`. Default
  DejaVuSansMono 20 px -> 12 px -> **32 columns**. `-s 24` gives 27, `-s 16` gives 38.
  `tcard` cannot see tp's flags through a pipe, so width is ours to set.
- Lines longer than tp's own columns are re-wrapped, which garbles a card. Card
  lines must be <= tp's columns. Default 32 is safe for any tp font <= 20 px.
- `tp` folds to ASCII and **drops** every glyph it cannot map. The local `tp`
  keeps any glyph the font draws in one cell (probe-rendered against a
  private-use codepoint), so `•`, `●` and `○` survive; anything else non-ASCII is
  dropped. Card output therefore carries only those three glyphs: no box
  drawing, no em dashes, no ANSI escapes.
- stdin text prints 40 lines per page, 3 s gap between pages, then one feed.
  Every line over 40 costs a 3 s pause.
- `tp FILE.png` rasterizes at 384 px, hard threshold, no dithering. stdin never
  reaches that path today; that is the delegated change.

## Data source

- `https://5e.tools/data/spells/index.json` maps 19 book codes to filenames.
- The GitHub mirror is DMCA-blocked (HTTP 451), so no commit pin is possible.
  Cache the fetched snapshot and key it by the sha256 of `index.json`.
- Fetch all `spells-*.json` on first use (~4 MB): name inference needs every
  book anyway, and one bulk fetch beats per-lookup requests.
- `fluff-spells-*.json` is never fetched.
- Spell records carry no class list, so cards have no `Classes:` field.

## Layout

```
FIREBALL       LEVEL 3 EVOCATION
================================
Casting Time: 1 action
Range: 150 feet
Components: V, S, M (a ball of
  bat guano and sulfur)
Duration: Instantaneous
--------------------------------
A bright streak flashes from you
to a point you choose within range
...
--------------------------------
AT HIGHER LEVELS
The damage increases by 3d6 for
each spell slot level above 3.
```

- `=` rule under the title, `-` rule before each block.
- A subtitle that wraps to one line is appended to the title row, right-aligned,
  when title + 2 + subtitle fits `cols`; the whole row is uppercase. A subtitle
  that starts with the title (V20's `Auspex` + `Auspex ●●●○○`) or needs wrapping keeps
  its own row and `-` rule, so nothing is repeated or crowded.
- Headings uppercase; body wrapped at word boundaries, continuation indented 2.
- Sources write list items as `- text`; the text backend prints `• ` with the
  continuation aligned under the text. `•`, `●` and `○` are the only
  non-ASCII characters that survive `fold()` (`tcard/glyphs.py`).
- VTM power cards show their level as pips in the subtitle (`Auspex ●●●`).
- Tables are kept as `Table` objects, not flattened: the text backend pads
  columns and shrinks the widest one until the grid fits `cols`, wrapping cells
  when a column hits its floor. The PNG backend gets the same rows to scale.
- `--brief` prints the header and field block only.

## Lookup

Positionals may omit leading parts; the rest is the name. A system selector is
always `family:edition` — `dnd:5e`, `pf:1e`, `pf:2e`, `vtm:v5`, `cp:2020`. A token with a
colon that is not a known system is a usage error, not part of a name.

```
tcard dnd:5e spell fireball
tcard dnd:5e fireball
tcard spell fireball
tcard fireball
```

- Exact case-insensitive match, then unique prefix, then substring, otherwise
  error with candidates on stderr and exit 1. Never fuzzy. Substring is the last
  tier, so `palm` finds "High Five, AKA The Palm Bomb" without stealing exact hits.
- Cross-book duplicates resolved by config `prefer` order; `--source` overrides.
- Ambiguity is real: Shield is both a spell and a magic item.

## Config

`~/.config/tcard/config.toml`, read-only, missing file = builtin defaults.

```toml
systems = ["dnd:5e"]
kinds   = ["spell"]
prefer  = ["XPHB", "PHB"]
cols    = 32
```

## Exit codes

0 printed, 1 no unique match, 2 usage or config error, 3 cache or network failure.

## Out of scope for v1

PNG backend (delegated, needs the tp stdin patch), RTF, PDF, `--list`,
`--level`/`--class` filters, fuzzy matching, `reprintedAs` following,
write-back of config, items/monsters, Pathfinder 1e.

## Expansion: more 5e kinds

Added after v1, same `Card` model, no renderer change:

| Kind | Source file | Notes |
|---|---|---|
| `item` | `items.json` + `items-base.json` | rarity + type code expanded via `itemType`; `value` is copper -> gp; weapon damage or armour AC line; attunement |
| `class_ability` | `class/*.json` | merges `classFeature` and `subclassFeature`; `class:feature`, `subclass:feature`, `class:subclass:feature` |
| `subclass` | `class/*.json` | one record per (class, subclass, source) from `subclassFeature`; card lists every feature as `Level N: Name` |
| `invocation` `metamagic` `maneuver` `fighting_style` `pact_boon` `infusion` `rune` `arcane_shot` `elemental_discipline` `renown_boon` | `optionalfeatures.json` | one file, filtered by `featureType` (EI, MM, MV:B, FS:F/R/P/B, PB, AI, RN, AS, ED, RP) |
| `feat` | `feats.json` | category code `O` -> "Origin Feat" |
| `condition` | `conditionsdiseases.json` | conditions only |
| `action` | `actions.json` | includes the 2024 standard actions |
| `monster` | `bestiary/index.json` + every `bestiary-<src>.json` | 114 books, ~12 MB cached once; stat-block card |
| `background` | `backgrounds.json` | 2024 records already read as prose entries |
| `species` | `races.json` | 2024 also call it species; type/size/speed/darkvision/resistances fields, 2014 adds ability scores; subraces are not composed onto the base race yet |
| `variant_rule` | `variantrules.json` | `ruleType` C/O/V/VO -> Rule / Optional Rule / Variant Rule |

`subclass` takes an optional class prefix (`subclass rogue:assassin`); a prefix
that names no record returns no match instead of falling back. Features are
deduped by `(level, name)` inside each source, and both the 2014 and 2024
records exist so `--source PHB` still picks an edition. The subclass's own
feature (same name as the subclass) becomes the intro body rather than a
`Level N` heading.

Naming:

- System ids are `dnd:5e`, and `5e` is accepted as an alias; both appear in error text.
- `_` stands for a space in every name token and apostrophes are ignored when matching.
- `:` only introduces a class path, never a system selector unless the prefix is a known system family.

Duplicates resolve by `prefer = ["XPHB", "XDMG", "PHB", "DMG"]`, so 2024 records win by default.

`monster` needs no new layout: AC/HP/speed/saves/skills/defenses/senses/
languages/CR are fields, the six ability scores are two 3-column `Table`s, and
each of `trait`, `action`, `bonus`, `reaction`, `legendary`, `mythic`,
`lairActions`, `regionalEffects` becomes a section whose paragraphs are prefixed
with the feature name. Monster tags are resolved by the same tag renderer, which
grew `{@atk}`, `{@atkr}`, `{@h}`, `{@actSave}`, `{@actSaveFail}`,
`{@actSaveSuccess}` and `{@recharge}` for the 2024 stat-block phrasing.

Deferred: subrace composition, recipes, PNG backend (blocked on the `tp`
stdin patch).

## Pathfinder 1e (first non-5e system)

Source: `https://www.d20pfsrd.com`, HTML only, browser User-Agent required
(nginx answers 410 otherwise).

- Name index: 26 hardcoded letter pages under `/magic/all-spells/<letter>/`,
  parsed into `{name, url}` and cached as `~/.cache/tcard/pf1/index.json`.
  One-time cost is about 20 s; `--refresh` rebuilds it.
- Card: the individual spell page is fetched once per spell and cached under
  `~/.cache/tcard/pf1/pages/<slug>.html`.
- Parsing: `<h1>` gives the title, the first bold-label paragraph gives the
  school for the subtitle, `EFFECT`/`CASTING` paragraphs give `Label value`
  fields, `DESCRIPTION` paragraphs give the body. Other dividers open their own
  section. Site furniture ("Join Our Discord!") is dropped.
- No `source` field exists, so `--all` prints `Name (spell)` with no book code.

## Pathfinder 1e: many kinds from one sitemap

d20pfsrd exposes 23 WordPress page sitemaps (~27k URLs after skipping `/extras/`,
`/work-area/`, 3rd-party and `__trashed`). One cached `urls.json` feeds every
kind by path shape, so adding a kind is a predicate, not a crawl:

| kind | path shape |
|---|---|
| spell | 26 letter pages (`/magic/all-spells/<letter>/`) |
| feat / trait | `/<kind>/<category>/<slug>/` |
| racial_trait | `trait` records whose group is `racial` |
| equipment | `/equipment/...<slug>/` |
| magic_item | `/magic-items/...<slug>/` minus group pages |
| race | `/races/<group>/<slug>/` |
| archetype | `/classes/<group>/<class>/archetypes/<set>/<slug>/` |
| class feature family | `/classes/<group>/<class>/<family>/[<set>/]<slug>/`, one kind per family |
| prestige_class | `/classes/prestige-classes/<book>/<slug>/` |
| monster | `/bestiary/monster-listings/...<slug>/` (len >= 4) |
| deity | Archives of Nethys, `DeityDisplay.aspx?ItemName=<name>` |

Class features are not one `class_ability` kind. Each family is its own kind
(`rogue_talent`, `witch_hex`, `magus_arcana`, `alchemist_discovery`,
`rage_power`, `ki_power`, `arcane_school`, `arcanist_exploit`, `ninja_trick`,
`slayer_talent`, `bardic_masterpiece`, `wild_talent`, `weapon_training`,
`bloodline`, `mystery`, `curse`, `order`, `spirit`, `domain`), the same way 5e
splits invocations from metamagic. A leaf is an ability, not a collection page:
the slug must not repeat the family name or end with its last word, and the
`<set>` segment above it must be `paizo-*` or a generic hex set, which drops
publisher collections.

Traits keep the site's groups, addressed as `trait:<group>:<name>`
(`trait magic:aeromantic_affinity`, `trait racial:arcane_dabbler`). Names are
derived from the slug with the trailing `-trait`, `-racial-trait`, `-su`/`-ex`
and race qualifiers trimmed.

Every page is parsed by one generic parser (`pf1/page.py`): `<h1>` is the title,
`<p class="divider">` switches between stat and body mode, bold runs become
`Label: value` fields, long labelled values fall to prose, and `<table>` becomes
a `Table`. Cached pages are keyed by a hash of the URL because slugs repeat
across kinds. Licence lines and site furniture are filtered as junk. 3PP
filtering is a path heuristic; a few entries leak through.

Monster stat blocks need no special layout: `DEFENSE`/`OFFENSE`/`STATISTICS`
dividers keep stat mode, and `<br>` separates labels inside a paragraph.
Familiars and animal companions are `bestiary/monster-listings/...` pages too,
so `monster` covers them (`tcard pf1 monster owl`).

Archetype pages put each feature in an `<h2>`–`<h4>` heading, and headings are
now blocks too, so one archetype card lists every feature as its own section
(`tcard pf1 archetype acrobat`). The licence paragraph d20pfsrd appends to the
last rules paragraph is cut at `Copyright <year>`; a leftover book title of
under 60 characters is dropped.

Spell pages also embed a `Mythic <Name>` sub-block. It is a different spell, so
`page.parse` skips everything under a `Mythic` heading on a spell page (a school
line means the page is a spell) until the next heading or divider. `[Source]`
paragraphs and the OGL block under them are dropped too.

Deities are the one kind with a different host: deity write-ups are Product
Identity, so d20pfsrd has none. `tcard/sources/pf1/deities.py` reads Archives of
Nethys instead (`DeitiesByGroup.aspx` is a single page listing ~460 names; each
deity is one `DeityDisplay.aspx?ItemName=<name>` page). Its parser walks
`h1.title`/`h2`/`h3.framing` headings, keeps `<b>Label</b> value` pairs from the
`Details` block as fields, turns other headings into sections, and drops
`Source`, `Pathfinder Wiki`, the banner nav, `Nethys Note` lines, and the
"For Followers of X" cross-reference link lists.
Collections that keep one ability per page (rogue talents, hexes, arcana) work;
pages that list many abilities in one document do not split yet.

## Vampire: The Masquerade 5e

`vtm:v5` (aliases `vtm`, `v5`) reads `https://vtm.paradoxwikis.com`, which
answers every request — pages, `api.php`, `robots.txt` — with a 3 KB JS
challenge shell. Pages therefore go through `https://r.jina.ai/`, which returns
the same page as clean markdown (~1-2 s per page, cached). Loresheets are the
exception: the Paradox wiki only indexes them, so names come from
`whitewolf.fandom.com` (`Loresheet` index page plus `Category:Loresheets`, 160
records) and entries from each loresheet's own MediaWiki page.

Kinds and their shapes:

| kind | record | card |
|---|---|---|
| `discipline` | 12 disciplines, each with its powers | header fields plus one section per level of `- Power` bullets |
| `discipline` power | one table row per power | Cost / Pool / Opposing / Duration, then the book's prose and `System:` text |
| `clan` | 16 (clans, Caitiff, Thin-blood) | Disciplines field, the clan's history from the pack, then Bane / Variant Bane / Compulsion sections |
| `loresheet` | 160 | one section per dot level, heading carries `●○○○○` |
| `merit` / `flaw` | 170 rows of paired wiki tables | Dots field plus text, the pack's fuller entry when it matches; group addressing `look:beautiful` |
| `predator_type` | 18 sections | prose paragraphs plus bullets |
| `ritual` | 137 rows (108 Blood Sorcery, 29 Oblivion) | Level, Cost, Origin/Pre-requisite, Ritual Roll, then prose with Ingredients/Process/System |

The wiki's power tables only carry a one-line `Effect`, so the body text comes
from `sources/vtm/pack.py`: a pinned Foundry VTT compendium pack
(`DeathDaisy/daisys-complete-foundry-wod5e-compository`, commit
`8c735d0c6c84a033cb17d92f903178506f9084ce`, `packs/disciplines/000028.ldb`,
387 KB) fetched once and cached as bytes (`cache.get_bytes`). A Foundry pack is
a LevelDB SSTable with snappy-compressed, prefix-compressed data blocks, so the
module vendors a ~120-line reader (`_snappy`, `_varint`, `_block`, `entries`,
`read_pack`) rather than adding a dependency. Each item is
`{"name", "type": "power", "system": {"description": "<p>…</p><p>■ Cost: …"}}`;
the page counts are rituals 79, oblivion 23, protean 22, ceremonies 22,
obfuscate 21, animalism 20, sorcery 20, fortitude 18, presence 17, celerity 16,
dominate 16, auspex 16, potence 15, alchemy 7.

`details()` turns a description into prose paragraphs plus a field map: the
`■ Label: value` runs are split off, `Dice Pools` becomes `Pool` and
`Opposing pool(s)` `Opposing` (so the value fits on the label's row),
`Prerequisite Power`/`Prerequisites` becomes `Prerequisite`, `Ingredient`
`Ingredients`, `Activation Cost` `Activation`; `Pool` is split on `" vs "` into
`Pool` + `Opposing` when the pack omits a separate opposed pool. `Source:` runs
are dropped. `◻` sub-bullets become `- ` lines and stay attached to their
label, and `body_lines()` emits the first line as `Label: text` with each
bullet as its own card line. `System` and the ritual-only
`Ingredients`/`Process` are body text, not fields.

The pack's text came out of a PDF, so words arrive split (`vam pire`,
`Story teller`) and some hyphens are missing (`non consenting`). `SPLITS` is a
curated 106-entry table of the broken forms seen across all 312 descriptions,
applied case-insensitively with the line's own capitalisation preserved. No
system dictionary is available at runtime, so this is a table rather than a
heuristic join.

Anything the pack lacks (29 wiki rituals and 7 ceremonies have no match, plus
a handful of disciplines the pack typos) keeps the wiki `Effect` as its body,
so a card never comes out empty.

The same repository supplies two more tables, listed in `PACKS`:
`advantages-flaws/000026.ldb` (177 items, 147 of them `type: "feature"` with
`featuretype` merit/flaw/background and a 0-5 `points` value) and
`clans/000028.ldb` + `clans/000035.ldb` (15 clans, listed twice). `items(pack)`
loads every table for a kind and merges them by name.

Merits and flaws use `feature()`: the wiki keeps only a merit's opening clause,
so the pack's description (book text, median 271 characters against the wiki's
115) replaces it. Pack names carry dot prefixes and credit lines
(`• Zeroed`, `Flaw: (••) Repulsive`, `Background: ...`), so `_feature_key`
strips those, lowercases through `normalize`, and drops `the`/`a`/`an`; the
pack's own typos (`Semblance of Methusela`, `Carenating Blood`) fall to a
`difflib.get_close_matches(cutoff=0.9)` pass. That matches 135 of the wiki's
220 records; the other 85 come from books the pack does not carry and keep the
wiki text.

`clan()` returns the clan's `description` prose as the card's opening section
(empty heading, so no title row) with the embedded `Disciplines:` line dropped.
The pack has no variant bane or compulsion, so those still come from the wiki.


Container kinds take a part after the colon, resolved by
`split_path`: `auspex:scry_the_soul`, `brujah:bane` (`bane_2` is the variant),
`brujah:banes` (both), `bahari:ritual_scarification` or `bahari:2`,
`blood_sorcery:astromancy`.

Clan affinity is not printed on discipline cards: the wiki renders it as icon
images, which the proxy strips, and the same information is on the clan cards.

Dot ratings are the one place a card leaves ASCII. `render/layout.fold` keeps
`●` (U+25CF) and `○` (U+25CB) after transliteration, because DejaVu Sans Mono
draws both at exactly the advance of `i`/`W`, so a 32-column line stays 32
columns of ink. `tp` keeps any glyph its font can draw (it compares each
character's mask against a private-use `.notdef` probe), so the same card prints
circles instead of blank cells.

## Pathfinder 2e

`pf:2e` (alias `pf2`) reads `https://github.com/foundryvtt/pf2e`, branch
`v14-dev`, which stores every rules element as one JSON file under
`packs/pf2e/<pack>/`. The repo is 2.1 GB, so the adapter keeps a blobless
sparse checkout at `~/.cache/tcard/pf2/repo`:

- `git clone --depth 1 --filter=blob:none --sparse --branch v14-dev` once (~16 s)
- `git sparse-checkout set --no-cone packs/pf2e/<pack>/ ...` for the packs a
  kind needs (cone mode cannot express the `*-bestiary` wildcard)
- `--refresh` does `fetch --depth 1` plus `reset --hard FETCH_HEAD`

Packs requested so far are remembered in `packs.json`, so adding a kind never
drops the earlier ones. Files whose name starts with `_` are skipped:
`_folders.json` is a list, not an item.

| kind | pack | count |
|---|---|---|
| `spell` | `spells` | 2035 |
| `feat` | `feats` | 6486 |
| `equipment` | `equipment` | 6004 |
| `ancestry` / `heritage` | `ancestries`, `heritages` | 54 / 358 |
| `class` / `class_feature` | `classes`, `class-features` | 29 / 883 |
| `deity` | `deities` | 483 |
| `monster` | core bestiaries, `npc-gallery`, `*-bestiary` | 7789 |
| `background`, `condition`, `action`, `hazard` | respective packs | 548 / 43 / 593 / 53 |

Item JSON is `{_id, folder, img, name, system, type}`; the builder is chosen by
`type` (`spell`, `feat`, `npc`, `ancestry`, `heritage`, `background`, `class`,
`deity`, `condition`, `action`, `hazard`), falling back to the equipment shape.

Card fields per kind:

- **spell** — subtitle `Spell N` (or `Cantrip`), Traditions, Cast, Range,
  Targets, Requires, Cost, Area, Defense, Duration, Traits. PF2 uses rank, not
  spell level; `system.level.value` is the rank.
- **feat** — subtitle `<Category> Feat N`, Prerequisites, Action, Frequency,
  Trigger, Requires, Traits.
- **equipment** — Price, Bulk, Damage, AC, Dex Cap, Check Penalty, Speed
  Penalty, Strength, Category, Usage, Traits.
- **ancestry / heritage / background** — HP, Speed, Size, Vision, Boosts,
  Flaws, Languages, Traits, trained skills. A boost bucket listing all six
  abilities prints as `free`.
- **deity** — Domains, Alternate Domains, Divine Font, Skill, Weapon,
  Sanctification, plus a cleric-spells section.
- **monster** — Perception with senses, AC, HP, Saves, Speed, Skills (with
  modifiers), Immunities / Weaknesses / Resistances, Traits with size,
  Languages; then a one-row ability-modifier `Table`, the flavour text, and one
  section per embedded ability item.

`system.description.value` is HTML and is parsed with the same markup helpers
PF1 uses (`pf1.html`): paragraphs become body text, `<ul>` becomes `- ` bullets,
`<table>` becomes a `Table`, and `<hr>` splits the description so that
`Heightened (+1)`, `Critical Success`, `Success`, `Failure` and `Critical
Failure` start their own sections.

Descriptions also carry Foundry macros, expanded before wrapping by
`pf2/macros.py`: `@UUID[Compendium.pf2e...Item.Off-Guard]{off-guard}` uses the
label, a bare `@UUID[...]` uses the last dotted segment, `@Damage[2d6[fire]]`
becomes `2d6 fire` (bracket-depth aware, because PF2 nests brackets),
`@Check[type:reflex|dc:20]` becomes `DC 20 Reflex`, and
`@Template[type:burst|distance:20]` becomes `20-foot burst`.

## Cyberpunk 2020

Data comes from `https://cybersmily.net/json`, which publishes the whole
dataset as static files (no bot gate, no rendering). Files are cached in
`~/.cache/tcard/cp-2020/files/` and parsed with `utf-8-sig`, because at least
`data/moreguns.json` carries a UTF-8 BOM.

| kind | endpoint | records |
|---|---|---|
| weapon | `wpns/cp2020weapons.json` + `data/moreguns.json` | 666 |
| armor | `data/cp2020armor.json` | 51 |
| cyberware | `data/cyberware.json` | 752 |
| program | `apps/nrmap/cp2020programs.json` | 281 |
| vehicle | `apps/maxmetal/cp2020-vehicles.json` | 246 |
| role | `apps/chargen/cp2020rolesext.json` (`{"roles": [...]}`) | 98 |
| skill | `apps/chargen/cp2020skills.json` | 215 |
| martial_art | `wpns/cp2020martialarts.json` | 23 |
| weapon_option | `wpns/cp2020weaponoptions.json` | 88 |
| corporation | `data/corporations.json` | 239 |
| 22 gear kinds | `data/cp2020equipment.json`, split by shop category | 742 |

Equipment is one kind per shop category (`electronics`, `security`, `drugs`,
`medical`, `tools`, `surveillance`, `communication`, `lifestyle`, `demolition`,
`military_gear`, `transport`, `braindance`, ...), the same rule that gives PF1
one kind per class-feature family. A single `equipment` bucket would make
`--all` useless and kind inference ambiguous.

Field mapping is mostly literal: `wa` is Accuracy, `conc` is Concealability
(`N`/`J`/`L`/`P`), `avail` Availability (`P`/`C`/`R`/`E`), `rel` Reliability
(`ST`/`VR`/`UR`), `hc` is Humanity Cost, `baseSP` Stopping Power, `ev`
Encumbrance, `bookcost` is vehicle cost. Armour prints its per-location SP as a
`Table`; martial arts print one row per manoeuvre with a signed bonus.

The data has no prose for weapons, roles or skills, so weapon descriptions are
fetched from `https://cyberpunk.fandom.com` (`action=parse&redirects=1`):
`cp/wiki.py` drops `<ref>`, `{{templates}}` (brace counted), `{| tables |}`,
`[[File:]]`, and stops at `Gallery` / `References`. A weapon without a wiki page
prints its stat block only; the fetch returns `None` rather than failing.

Names contain hyphens where the query uses underscores, so `cp` matches with
`-` read as a space (`hip_mounted_powerpack` → `Hip-Mounted Powerpack`) while
keeping exact, prefix, then substring semantics. Substring is the last resort,
so `cyberware palm` finds `High Five, AKA The Palm Bomb`; several hits still go
through the ambiguity path rather than a silent pick.

### Full field coverage

Every non-empty key reaches the card. Weapons additionally print `category`
(book grouping: Pistols, Exotics, Launched Grenades), `subcategory`, `fullAuto`
/ `burstFire` as Firing Modes, `burst` (blast radius for grenades and mines),
`ap` as Armour Piercing, `thrown`, `bod` as Minimum BOD, and the record's own
`notes`. Cyberware prints `subtype`, `numOptions` as Option Slots, and always
prints Humanity Cost and Surgery when the key exists, even when the value is
`0` or `None`. `abbrev` is deliberately not printed. Skills print `option` and
`maBonuses` (manoeuvres); weapon options print `costMultiplier` as `x0.25`;
roles print the `secondary` skill list.

Cyberware subtitle is the record's own type, so `BIOWARE` reads as Bioware and
`EXOTIC BODYSCULPT` as Exotic Bodysculpt: biosculpting is a kind of bioware but
stays a separate type. Both live in the single `cyberware` kind.

### datafortress2020 cyberware

Two pages on that site carry structured implant data:

- `https://www.datafortress2020.com/bio.htm` — the bioware tables, 41 items
  across eight sections. Each item is a `Type | Cost | HC | Surgery Code` row
  followed by an `Effect` row.
- `https://www.datafortress2020.com/ultrachrome/Cyberware.html` — "The
  Illustrated Reference Guide Volume 3", a 500 KB Word export listing 624
  cybernetic items from every CP2020 product. Its paragraphs cycle through an
  image, a name, then a stat line: surgery code, effect text, then
  `bookRef HC cost` at the end. `parse_stats()` splits those tokens from the
  right, validates the book reference and the two numbers, and takes the
  nearest all-caps paragraph as the item's type.

The two pages are merged into the cyberware list, keyed by normalised name: 752
records from cybersmily plus 243 catalogue-only items. Both also fill `hc`,
`surgery` and the effect text where the JSON leaves them empty. The certificate
has expired, so the fetch uses an unverified context; pages are cp1252. The
rest of datafortress is a PDF archive (`fileproject/details.php?image_id=…`).

## Vampire: The Masquerade 20th Anniversary

V20 comes from `whitewolf.fandom.com` through the MediaWiki API
(`action=query&list=categorymembers` for name indexes, `action=parse` for
wikitext), cached in `~/.cache/tcard/vtm-v20/`. The wiki needs the edition
suffix in its category names: `Category:Discipline (VTM)`,
`Category:Clans (VTM)`, `Category:Bloodlines (VTM)`, `Category:Paths`.

| kind | source | records |
|---|---|---|
| discipline | `Category:Discipline (VTM)` | 67, each with its power list |
| clan | `Category:Clans (VTM)` minus concept pages | 41 |
| bloodline | `Category:Bloodlines (VTM)` minus concept pages | 97 |
| ritual | seven `List of ... Rituals` pages | 337 |
| path | `Category:Paths` | 105 |
| merit / flaw | `List of Merits and Flaws (Storyteller System)` | 401 |

Discipline pages list every published power in one section
(`Official Abilities`), with a `{{dot|N}}` marker per level and
`** '''Name''': text` per power. Powers have no pages of their own (they
redirect back to the discipline), so the one-line description on that page is
the whole text a power card can carry. Power cards are addressed
`auspex:heightened_senses`, and the whole discipline prints each level's
powers with their descriptions, the same container/sub-part rule as `vtm:v5`.

Clans and bloodlines share a page shape: an `{{Organization}}` infobox whose
`disciplines`, `nicknames` and `faction` keys become fields, then
`==Overview==` prose, `====Banes====` bullets under `==Weaknesses==`, and a
`===Compulsion===` paragraph. Clans take `brujah:bane`, `:banes`,
`:bane_1`, `:bane_2` and `:compulsion`, matching the v5 spelling.

Not every page has an `Overview`: `Cappadocian`, `Ahrimanes` and about a sixth
of the 143 clans and bloodlines open straight into `==History==` or
`==Background information==`. The card's opening prose therefore falls back
through those headings, which is what fixed the head-only clan cards. Only the
first paragraph (two when an `Overview` exists) rides the card, because the
pages are long: measuring every level-2 section except navigation gives a
median of 29 printed lines but 251 at the 75th percentile and 900–1100 for
Banu Haqim, Tremere and Baali. The remainder is the `:lore` part (aliases
`:history`, `:background`), which prints every section that has text, minus
`references`, `gallery`, `see also`, `trivia`, `external links`, `stats`,
`quotes`, and any heading naming members, legacies, loresheets, a character
sheet or character creation. Subsection headings that carry no prose of their
own (`==History==` over `===Dark Ages===`) drop out with the empty body.

Rituals are split across seven tradition list pages in two layouts:
Thaumaturgy is a `Name | Ingredients | Process | Effect | Developer` wikitable
under `Rank N` headings, while the others are `* {{dot|N}}` markers with
`** '''Name''': text` bullets. Both map onto the same card
(Level, Ingredients, Process, Developer fields plus the effect as body).
Addressing is `thaumaturgy:bind_the_accusing_tongue`,
`necromancy:knowing_stone`, or a bare name.

Merits and flaws come from one large list page: `==Merits==` and `==Flaws==`
sections, group headings (`One`, `Two`, `Variable`, ...), a table per group or
`'''Name''' text` paragraphs. Short book markers in brackets are stripped.
Addressing is `one:ambidextrous`, `two:blind`, or a bare name.
